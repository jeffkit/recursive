# Phase 5 — infrastructure fixes from the 2026-08-03 rescue (supervisor)

Date: 2026-08-03. Source: rescue of self-improve runs
`selfimprove-1785742915472` (G1/377), `selfimprove-1785743345785` (G2/378),
`selfimprove-1785743355828` (G3/379). All three runs' cargo-mutants verification
failed; supervisor stopped flows and landed the three goals manually (main:
`168a122`, `46ba0d5`, `d580f4e`).

## 1. Disk ENOSPC kills cargo-mutants `--in-place` (P1)

**Evidence**: G2 first mutants run failed with `No space left on device (os error 28)`
writing the mutated `a2a.rs`. Worktree `target/` dirs grew to 64G+ (main 44G + 3
worktrees ~20G); three concurrent runs compiling at once exhausted the ~7G free space.

**Fixes (pick)**:
- flow preflight: refuse to start a run when free disk < 20G (or 2× worst-case target);
- after a run finishes/preserves, delete its worktree `target/` (or `git worktree
  remove --force`); keep a shared `CARGO_TARGET_DIR` so incremental artifacts are reused
  across worktrees instead of duplicated;
- cargo-mutants in copy mode writes into its own scratch dir, but compile artifacts still
  land in the target dir — the space check is the real guard.

## 2. Mutants gate timeout: 40min < ~65-75min actual (P1)

**Evidence**: `agent-mutants.sh` runs `--jobs 1` (`--in-place`, single-threaded). G2 log:
`MISSED ... in 21s build + 38s test` ≈ 60s/mutant; 65-69 mutants ≈ 65-75min; gate timeout
is 2400000ms (40min) + 15s watchdog → guaranteed timeout on every attempt. Goal 376
already hit this (86min error landed).

**Fixes (pick)**:
- default `--jobs $(nproc)` (>1 → copy mode, no source mutation, and sidesteps
  assert_clean entirely);
- raise gate timeout to 2h;
- reduce per-mutant cost (incremental build is already the main lever; verify with
  `--jobs 6 --file <f>`).

## 3. assert_clean vs flow ordering: first mutants attempt always fails (P1)

**Evidence**: flow runs quality gates BEFORE `commit.prep/land`, so the agent's changes
are uncommitted when `agent-mutants.sh` runs → `assert_clean` refuses (`exit 3`) → first
attempt dies in 1s (G1 08:00:57, G2 16:04:20) wasting a fix round on every src-touching
goal.

**Fixes (pick)**:
- commit the worktree before mutants-class gates (or move commit.prep before gates);
- or: in `assert_clean`, if the target file has uncommitted changes, fall back to
  `--jobs >1` copy mode instead of refusing (still fast, no clobber risk).

## 4. Mutants log is block-buffered — monitoring misreads it as hung (P2)

**Evidence**: `cargo mutants ... > /tmp/agent-mutants-run.log 2>&1` buffers 4KB; the log
appears frozen (G1: 20min at "baseline ok") while cargo-mutants actually runs. Supervisor
misjudged running processes as hung (CPU 0% = waiting on children; no stdout progress due
to buffering).

**Fixes (pick)**:
- wrap mutants runs with line buffering (`script -q /dev/null ...` or
  `stdbuf -oL` where available), or
- teach the monitor: check child processes (`ps --ppid`), file mtime growth, and
  `lsof` before declaring a hang; distinguish "no progress" from "buffered progress".

## Lesson for the supervisor (self)

Before killing a "hung" process: check `ps --ppid` (children), file mtime, and
`lsof`/`sample`. Block-buffered output + child-waiting look exactly like a hang.
