# Manual edit: goal-355 — Replace unsound `serde_yml 0.0.12` with `serde_yaml_ng` (RUSTSEC-2025-0068)

**Date**: 2026-08-01
**Goal**: Remove the unmaintained, UB-flagged `serde_yml` crate (RUSTSEC-2025-0068 —
`Serializer.emitter` undefined behavior) from the dependency graph. Pure dependency
swap + path-prefix rename; no kernel/tools/invariant changes.

## Why

`serde_yml 0.0.12` is covered by RUSTSEC-2025-0068 (unsound serializer, unmaintained).
This codebase only **deserializes** YAML (`serde_yml::from_str` at 2 sites), so the UB
is not reachable today, but the crate stays on the dependency graph and blocks
`cargo audit`/`cargo deny` gates. The advisory's recommended remedy is a maintained
fork — chose **`serde_yaml_ng`** (most widely adopted; `from_str` API identical to
`serde_yaml`/`serde_yml`).

## Files touched

- `Cargo.toml` — `serde_yml = "0.0.12"` → `serde_yaml_ng = "0.10.0"` (verified on
  crates.io: 0.10.0 is latest, `features: {}` — no feature flag needed, it re-exports
  serde like the original `serde_yaml`).
- `Cargo.lock` — regenerated by `cargo build`: `serde_yml` removed (grep count 0),
  `serde_yaml_ng 0.10.0` + `unsafe-libyaml 0.2.11` backend added.
- `src/tools/agent_defs.rs` — 3 `serde_yml` references renamed to `serde_yaml_ng`:
  - doc comment on `AgentDefinitionRaw` (was "so `serde_yml` can give us a flat …")
  - `:199` production — `serde_yml::from_str(&frontmatter)` in `parse_file`; the
    surrounding `.map_err(|e| Error::Config { message: format!(...{e}...) })` needed
    **no** change: `Error::Config` takes a `String` and the error is formatted via
    `Display`, which both `serde_yml::Error` and `serde_yaml_ng::Error` implement.
  - `:284` test — `serde_yml::from_str(&front).unwrap()` in `frontmatter_multiline_prompt`.

## Tests added

**Follow-up (agent-presence gate round):** the `agent-test-presence` gate requires a
`#[test]` marker on an *added* diff line — a pure rename of existing lines (even inside
the test module) does not count. Added two tests in `src/tools/agent_defs.rs`:

- `parse_file_invalid_yaml_is_config_error` — exercises the changed `:199` production
  path's **error** branch: well-formed `---` delimiters but malformed YAML body
  (`system_prompt: [unclosed flow`), asserts the `serde_yaml_ng::from_str` error is
  wrapped into `Error::Config` whose message contains `Invalid YAML frontmatter` and
  the offending file path. (The happy path was already covered by `parse_full_file`;
  the error path was not.)
- `load_registry_reports_non_empty_and_iter_yields_definitions` — pins
  `AgentDefinitions::is_empty()` returning `false` for a non-empty registry and
  `iter()` actually yielding the loaded definitions. Pre-emptive fix for the
  `agent-mutants` gate: scoped mutation run showed 2 surviving (pre-existing) mutants
  on the changed file (`is_empty -> true`, `iter -> empty`) that would fail the gate
  even though they are unrelated to the YAML swap.
