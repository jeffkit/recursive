# Manual edit — issue #120: make "where did it get stuck" answerable

- Date: 2026-10-07
- Goal: issue #120 (P1) — transcript has no step/turn, checkpoints default
  empty, failure events are all silent.
- Baseline: fc29f3d4 (origin/main at filing)

## What changed

1. **`TranscriptEntry.step: Option<usize>`** (`src/session/serialize.rs`).
   Populated from the kernel: `AgentEvent::MessageAppended` /
   `MessageAppendedWithAudit` gained a `step: Option<usize>` field, set in
   `RunCore::push_message` / `push_tool_result` from the loop's step. The
   `SessionPersistenceSink` threads it into `SessionWriter::append_with_audit`.
   Runtime-level messages (user turn, compaction summaries, post-compaction
   re-injections) carry `None`. Field is `#[serde(default)]` so pre-#120 rows
   still load.

2. **`AgentEvent::TurnFailed { step, error }`** (`src/event.rs`) emitted from
   `RunCore::fail_step` — the kernel's `Err` return path. Previously an `Err`
   bubbled straight out of `run_inner`, leaving the sink with no
   `TurnFinished` and no failure signal at all.

3. **`HookEvent::SessionEndErr { error }`** (`src/hooks/mod.rs`) dispatched by
   `AgentRuntime::run` when a turn returns `Err` (`record_turn_failure`).

4. **Failure fallback checkpoint** (`AgentRuntime::write_failure_checkpoint`).
   When a turn ends in `Err` and checkpoints are enabled, the runtime snapshots
   the workspace and appends a `CheckpointRecord` labelled `failure: <error>`.
   This keeps `checkpoints.jsonl` from being empty after a crash (Goal 284 made
   snapshots on-demand), so `sessions rewind` has a restore point.
   `checkpoint_log::unix_now` was promoted to `pub` (single definition,
   `tools::checkpoint` now calls it).
